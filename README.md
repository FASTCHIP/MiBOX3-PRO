# Xiaomi Mi Box 3 Pro (MiBOX3_PRO / kungfupanda)

Рабочие заметки и инструменты по приставке **Xiaomi Mi Box 3 Pro**: что реально работает,
что не работает и как это проверялось. Всё, что здесь публикуется, проведено на живом устройстве.

## Железо и система (проверено на устройстве)

| Параметр | Значение | Как получено |
|---|---|---|
| Модель | `MiBOX3_PRO` | `getprop ro.product.model` |
| Кодовое имя | `kungfupanda` | `getprop ro.product.device` |
| SoC | MediaTek **MT8173** | файлы `init.mt8173.rc`, `fstab.mt8173.rc` в корне ФС |
| Android | 5.1 (SDK 22) | `getprop ro.build.version.release` |
| Root | есть, `su` в `/system/bin/su`, менеджер **SuperSU** (`eu.chainfire.supersu`) | `ls -l /system/bin/su`, активность запроса root |
| Сетевой интерфейс | только `wlan0` (eth0 отсутствует, при этом `dhcp.eth0.ipaddress` может содержать устаревший адрес) | `ls /sys/class/net` |

## Сетевой ADB (рабочий способ отладки)

На этой приставке ADB по USB-кабелю **не работает** (подробнее ниже), зато работает сетевой ADB.

Включается двумя свойствами и перезапуском демона:

```sh
su -c "setprop service.adb.tcp.port 5555;setprop persist.adb.tcp.port 5555"
su -c "stop adbd;start adbd"
```

`persist.adb.tcp.port` делает настройку постоянная: после перезагрузки приставка сама слушает
`5555`, повторно запускать приложение не нужно.

Подключение с ПК:

```sh
adb connect <IP-приставки>:5555
```

При первом подключении на экране ТВ появится запрос авторизации ключа — нужно подтвердить
(галка «Всегда разрешать» сохраняет ключ, и повторных запросов не будет).

### MiBoxADB — приложение для включения сетевого ADB

Готовый APK: [`apk/MiBoxADB-v1.1.apk`](apk/MiBoxADB-v1.1.apk)

```
sha256  fbce236774414e97f71f68673913891554424fac1cf06cfd3340479facbdabf6
размер  12627 байт
package ru.neftreserv.miboxadb, versionCode 2, versionName 1.1
разрешения: не требуются
```

Что делает при запуске: показывает модель/SDK/состояние `adbd`, затем через `su` выполняет
команды выше и печатает код возврата каждой из них, после чего показывает IP-адрес
(`wlan0`/`eth0`) и строку для `adb connect`. Если root ещё не подтверждён в SuperSU, приложение
повторяет попытку через 8 секунд.

Установка: файл APK на флешку или в `Download`, открыть через проводник, подтвердить установку;
при запросе SuperSU нажать «ПРЕДОСТАВИТЬ».

Сборка из исходников (apktool + smali, SDK не нужен):

```sh
apktool b . -o unsigned.apk
apksigner sign --ks release.keystore --ks-key-alias hermes unsigned.apk
```

Подписывающий ключ в репозиторий не попадает: он должен быть только у автора, иначе обновления
не установятся поверх уже установленного приложения.

## ADB по USB: почему не получается (проверено)

При включённой отладке приставка переходит в режим gadget: `sys.usb.config=mtp,adb`,
`sys.usb.state=mtp,adb`, `init.svc.adbd=running`. Windows слышит подключение, но устройство
перечисляется как битое:

```
ИД экземпляра: USB\VID_0000&PID_0002\...
Описание:      Неизвестное USB-устройство (сбой запроса дескриптора устройства)
Код проблемы:  43 (CM_PROB_FAILED_POST_START)
```

Проверено: два разных порта на ПК дают одинаковую картину; драйвер тут не при чём (VID/PID не
читаются, привязывать не к чему); кабель прозванивался; BROM-режим MediaTek (`0E8D:201C`) не
появляется. Вывод: проблема на уровне электрики/конфигурации порта, сетевой ADB — рабочий путь.

## Как это проверялось (чтобы не переделывать)

- `getprop`/`id`/`ls /sys/class/net` — через уже поднятый сетевой ADB.
- Установка APK по сети (`adb install`, `pm install`) на этой приставке зависает: Patchwall/SuperSU
  показывают модальное окно, которое нужно подтвердить пультом. Это нормально, не «зависание».
- Диалог SuperSU не отдаёт свои кнопки в `uiautomator`, поэтому автоматизировать подтверждение
  root нельзя — его нажимает человек на телевизоре.
